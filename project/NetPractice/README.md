## 前置知识

### 子网划分（Subnetting）

- **子网掩码（Subnet Mask）**决定了子网的大小，比如：
    - `/24 → 255.255.255.0`：256 个地址
    - `/25 → 255.255.255.128`：128 个地址
    - `/17 → 255.255.128.0`：32768 个地址
- 子网中：
    - 第一个地址是**网络地址**（不可分配）
    - 最后一个地址是**广播地址**（不可分配）
    - 其余地址是**主机地址**

要使两台主机能通信，它们必须：

> 在同一子网（相同网络地址，掩码匹配）

举例来说：

```
网络地址：192.168.1.0/24
子网掩码：255.255.255.0
```

CIDR (Classless Inter-Domain Routing) 表示法（例如/23、/24、/28、/32）直接表示子网掩码中1的位数。

这里的 `/24` 表示子网掩码的前 24 位是 1，后 8 位是 0。换句话说，一个 `/24` 子网包含 $2^8 = 256$ 个地址，从 `192.168.1.0` 到 `192.168.1.255`。

* 其中 `192.168.1.0` 是该子网的**网络地址**，不能分配给主机。
* `192.168.1.255` 是该子网的**广播地址**，也不能分配给主机。
* 可以分配给主机的地址范围是 `192.168.1.1` 到 `192.168.1.254`。

因此，在不借助路由设备的前提下，只有当多个主机的 IP 地址都落在同一个子网范围内（例如 `192.168.1.x`，其中 $1 \leq x \leq 254$），它们之间才能直接通信。

要判断两个 IP 是否在同一子网中：

比如有：

- A 的 IP 是：`104.198.243.125/16 → 掩码 255.255.0.0`
- C 的 IP 是：`104.198.243.297/25 → 掩码 255.255.255.128`

用 子网掩码 与 IP 做 按位与运算（AND）

比较得到的网络地址是否相同

### 私有地址段（RFC1918）

* RFC1918 是 IETF 发布的标准，标题为：
  > *Address Allocation for Private Internets*
* 定义了专门保留用于**私有网络通信**的 IP 地址段。
* 这些地址**不能在公网中路由**，专用于局域网（LAN）。

三个私有地址段（RFC1918 定义）

| 地址段           | 子网掩码      | 可用 IP 数 | 常见用途           |
| ---------------- | ------------- | ---------- | ------------------ |
| `10.0.0.0/8`     | `255.0.0.0`   | ~1677 万   | 大型企业、数据中心 |
| `172.16.0.0/12`  | `255.240.0.0` | ~104 万    | VPN、组织内网络    |
| `192.168.0.0/16` | `255.255.0.0` | ~6.5 万    | 家庭、小型局域网   |

1. 避免与公网地址冲突
   - 私有地址不会在公网中出现，确保不会路由冲突或泄漏。
2. 增强安全性
   - 私网地址默认不可被互联网访问，增加隔离与防护。
3. 节省 IPv4 资源
   - 私有地址可通过 NAT 转换共享一个公网 IP，实现海量终端共用公网地址。
4. 可重复使用
   - 同一个私网地址可以在多个局域网中重复使用，不需要注册，全球通用。

不能用于私网的地址段（示例）

| 地址段           | 用途 / 限制                                      |
| ---------------- | ------------------------------------------------ |
| `127.0.0.0/8`    | **回环地址**（loopback address），只用于本机测试 |
| `0.0.0.0/8`      | 保留地址，代表“任意地址”                         |
| `169.254.0.0/16` | 链路本地地址（APIPA）                            |
| `224.0.0.0/4`    | 多播地址                                         |
| `240.0.0.0/4`    | 实验性保留地址                                   |

应用场景示例

- 家庭路由器：
  - 常见网段：`192.168.0.0/24` 或 `192.168.1.0/24`
- 企业内网：
  - 部门划分：`10.0.0.0/16`, `10.1.0.0/16`，方便管理和隔离
- 虚拟机或 Docker 网络：
  - 默认使用私有地址段来配置内部通信网络

### 交换机（Switch）

交换机是一种工作在**数据链路层（第2层）**的网络设备，用于将多个主机连接在一起，实现它们之间的局域网通信，是最常用的 LAN 设备。

> 与集线器（Hub，已淘汰）不同，交换机具备转发决策能力，只将数据发送给目标设备，而不是广播给所有设备。

- 交换机是二层设备，根据 MAC 地址转发
- 不隔离广播域，因此：只要 IP 地址处于同一子网、MAC 层连通，主机就能通信
- 不做 IP 路由，因此不同子网不能直接通信

核心作用和功能有

1. 转发以太网帧（Frame Switching）
    - 根据帧头中的 MAC 地址 来判断目标设备在哪个端口。
    - 然后只把数据转发到该端口，实现点对点通信。
2. 构建局域网（LAN）
    - 将多台主机连接在一起组成局域网。
    - 每个主机插入交换机的一个端口，互相可见并通信。
3. 学习 MAC 地址（MAC Learning）
   - 交换机会维护一个MAC 地址表（MAC address table / CAM 表）。
   - 自动记录哪台设备在哪个端口上出现过（来源 MAC）。

   ```
   MAC 地址         接口端口
   AA:BB:CC:DD       Port 1
   DE:AD:BE:EF       Port 3
   ```
4. 广播/泛洪/Flooding 控制
   - 如果交换机暂时不知道目标 MAC 的端口，会将帧**广播**到所有端口。
   - 一旦学会，就只发送给目标端口。

### 路由器 (Router)

路由器则主要用于连接不同的网络，并在这些网络之间转发数据包，例如连接你的家庭局域网和互联网（广域网WAN）。

连接不同的网络（子网）。 路由器的每个接口通常连接一个不同的子网。

工作层次： 路由器工作在OSI模型的**网络层（第3层）**。

寻址方式： 它通过识别数据包的IP地址来决定最佳的转发路径。路由器维护一个路由表，记录着不同网络的IP地址和到达这些网络的路径。

主要功能：

- 连接不同网络： 例如将你的家庭网络连接到互联网。
- 数据路由： 根据IP地址和路由表，决定数据包在不同网络间的传输路径。
- 网络地址转换（NAT）： 允许局域网内的多台设备共享一个公共IP地址访问互联网。
- DHCP服务： 自动为连接到网络的设备分配IP地址。
- 防火墙功能： 提供基本的网络安全保护。
- 适用场景： 几乎所有需要连接互联网的家庭或企业网络都必须有路由器。


### 默认网关 (Default Gateway)

当一个设备需要与不在同一子网内的设备通信时，它会将数据包发送给其配置的默认网关（通常是连接其所在子网的路由器接口IP）。

同一子网内通信： 设备通过MAC地址直接通信（经过交换机）。它们不需要经过路由器。

跨子网通信： 设备必须通过路由器才能与不同子网的设备通信。发送方将数据包发送到其默认网关（路由器接口），路由器根据目标IP地址和其路由表将数据包转发到正确的目的网络。


### 路由选择

一、基本概念

* **路由器的职责**：根据目标 IP 地址，从其\*\*路由表（Routing Table）\*\*中查找最优路径，决定如何转发数据包。
* **路由表来源**：

  * 直连路由（Connected）
  * 静态路由（Static）
  * 动态路由（Dynamic，来自如 RIP、OSPF 等协议）
  * 默认路由（Default route，`0.0.0.0/0`）

---

二、选择原则（匹配与优先级）

**1. 最长前缀匹配优先（Longest Prefix Match）**

* 在多个匹配项中，选择**子网掩码最长**（即匹配位最多）的那一项。
* 示例：

  * `192.168.0.0/24` 与 `192.168.0.0/16` 同时匹配时，选择 `/24`

**2. 路由类型优先级**

当有多个等长前缀时，优先级如下：

| 优先级 | 路由类型               | 说明                   |
| --- | ------------------ | -------------------- |
| 最高  | **直连路由** Connected | 接口配置 IP 后自动添加，目标网络直连 |
|     | **静态路由** Static    | 管理员手动配置              |
|     | **动态路由** Dynamic   | 由路由协议生成              |
| 最低  | **默认路由** Default   | 匹配所有地址（如无其它匹配时使用）    |

---
三、直连路由说明

* 当某接口配置了 IP 地址后，该子网会自动加入路由表，作为直连路由。
* 对目标地址的判断优先匹配直连子网。
* 实际转发会：

  1. 查目标是否在直连网段内。
  2. 若是，直接通过该接口发出（需进行 ARP 获取 MAC）。

---

四、多个匹配项冲突时的决策流程（综合）

1. **查找所有匹配目标地址的路由项**
2. **选择最长前缀匹配**
3. **若有多个最长匹配，按路由类型优先级选择**
4. **若仍冲突（例如多条等长动态路由），根据管理距离（Administrative Distance）选择**
5. **最后根据 Metric（度量值，如跳数、开销等）选最优路径**

---

五、默认路由（0.0.0.0/0）

* 用于匹配**所有地址**，在无其他更具体路由匹配时使用。
* 常见于连接互联网的出站口（如下一跳为 ISP 路由器）。

### Level 5



- 路由表：指定特定子网的 `IP` 应该发送到哪个网关（gate）
  - `default` 默认路由，等价于 `0.0.0.0/0`

显然，这里的 client 的网关就是路由器上分别连接的 Interface，我们设置好 Client 的路由表，并确定它和网关的 IP 在一个子网即可



> [!NOTE]
>
> 客户端 IP 是否必须与网关在同一子网？
>
> **必须在客户端视角下处于同一子网**，否则客户端不会将数据包发往网关。
>
> 客户端发送数据时，会先判断：
>
> * **目标 IP 是否在本地子网内？**
>
>   * 是 → 直接发送
>   * 否 → 发给默认网关
>
> 但**无论目标是谁，客户端首先必须能发 ARP 请求找到网关的 MAC 地址**，前提是客户端“认为”网关在本地子网内：
>
> ```text
> (Client_IP & Netmask) == (Gateway_IP & Netmask)
> ```
>
> 若不满足这个条件，客户端不会尝试 ARP，因此通信失败。
>
> ---
> 
> 不同子网掩码是否一定不行？
>
> 不一定。只要**客户端的掩码下**网关仍然被视为“同一子网”，通信可以正常工作。
>
> 例如：
>
> * Client IP: `192.168.1.10/24`
> * Gateway IP: `192.168.1.1/25`
>
> 客户端视角下 `192.168.1.1 ∈ 192.168.1.0/24`，符合上式，通信正常。
>
> 但如果 Client 配置为 `192.168.1.130/25`，而网关是 `192.168.1.1/25`，则通信失败，因为客户端不认为网关在本地网段内，**不会发出 ARP**。

  - 这里限定了子网掩码和 Interface R23 的 IP地址
  - 显然子网为 `107.195.192.0/18`，给 Interface D1 任意选一个合适 IP 即可
- 对于 Client C （cation），他没有特殊要求，我们随机分配它所在子网为：`8.0.0.0/24`
  - 可以看到图中互联网路由表和路由R1侧写的 `8.0.0.0/8`，严谨点应该写成 `8.0.0.0/24` 但是这里无伤大雅
  - 配置好之后 cation可以通过路由 R2 与 gluton 通信
- Interface R13 和 R21 是一个子网，我们分配：`84.161.17.252/30`
  - 这里 R1 路由表前两条是要将访问上述两个子网的请求转发到路由 R2 上
  - 那为什么这里没有写明 Client A 和 B 所在的子网呢？因为这里的 Interface R11 直接和子网和交换机连接，优先级要高
  - 而上述两个子网（C、D）在路由 R2 之后

- A、B 所在的子网也比较自由，只有子网掩码限制，我们选择：`152.168.0.0/25`
